# 005 — CLI

**Status:** draft

Defines the command-line interface. Per the root README's planned shape, the CLI does the parsing, diffing, and patching, and is runnable locally; the GitHub Action of [006](006-ci-integration.md) is a thin wrapper around it.

## 1. Principle

- **005-R1** — Every CI behaviour MUST be reproducible locally with the same binary and flags. The Action MUST NOT implement logic of its own. A tool that edits your README should be debuggable without pushing a commit.

## 2. Commands

### `init`

Scaffolds `readmesync.config.json`, detecting language and available manifests.

- **005-R2** — `init` MUST NOT overwrite an existing config without `--force`.
- **005-R3** — `init` MAY insert marker pairs into the README for declared sections, but only with `--write-markers`, and only appended. It MUST NOT reposition existing content.

### `check`

Reports what would change. The read-only default.

- **005-R4** — `check` MUST NOT write to the working tree. This is the command CI runs on pull requests.

### `apply`

Regenerates affected sections and writes the README and state file.

- **005-R5** — `apply` MUST write atomically: temp file, then rename. A crash mid-write MUST NOT leave a truncated README.
- **005-R6** — `apply` MUST refuse to run on a dirty working tree unless `--allow-dirty`, so its edits are never entangled with uncommitted work.

### `explain <section-id>`

Prints the section's extractor, inputs, last input hash, confidence, and the paths that would trigger it. The debugging command for "why did this not regenerate".

## 3. Global flags

| Flag | Default | Effect |
|---|---|---|
| `--config <path>` | `readmesync.config.json` | Config location. |
| `--scope <name>` | all | Restrict to one monorepo scope. |
| `--all` | off | Ignore the diff; treat every section as affected. Cold start on demand. |
| `--since <ref>` | state | Override the diff base, bypassing `lastCommit`. |
| `--confidence <n>` | config | Override the threshold. |
| `--format <text\|json>` | `text` | Output format. |
| `--dry-run` | off | Valid on `apply`; behaves as `check` but reports as `apply` would. |
| `--verbose` | off | Per-section decisions and input hashes. |

- **005-R7** — `--format json` output MUST be schema-stable and MUST contain no ANSI codes, so CI can parse it.
- **005-R8** — Diagnostics go to stderr; machine-readable output goes to stdout. Piping `--format json` MUST yield valid JSON alone.

## 4. Exit codes

| Code | Meaning |
|---|---|
| `0` | Success. Nothing to do, or changes applied. |
| `1` | Changes needed. `check` found sections that would be rewritten. |
| `2` | Stale warning. At least one section fell below threshold (002-R13). |
| `3` | Config error. Invalid, missing, or unknown extractor. |
| `4` | Parse error. Malformed markers (001-R4, 001-R5). |
| `5` | Internal error. |

- **005-R9** — `1` and `2` are distinct so CI can fail on drift while merely reporting low confidence, which is what makes fail-closed usable rather than obstructive.
- **005-R10** — When several conditions hold, the highest code wins.

## 5. Output

```
$ readmesync check

  ~ api           regenerate    3 inputs changed        confidence 0.90
  ! changes       stale         commit history unclear  confidence 0.60  (threshold 0.80)
  = dependencies  unchanged     input hash match
  - structure     skipped       no matching change

  1 section would be rewritten, 1 stale warning.
  Run with --verbose to see triggering paths.

exit: 2
```

- **005-R11** — Every section in config MUST appear in `check` output with an explicit disposition. Silence about a section is indistinguishable from a bug.

## 6. Acceptance criteria

- `check` on a clean tree exits `0` and writes nothing.
- `check` after a source change exits `1` and names the affected sections.
- A section below threshold produces exit `2`, and `apply` leaves that section byte-identical.
- `apply` interrupted mid-write leaves the original README intact (005-R5).
- `--format json` parses as JSON with stdout captured alone (005-R8).
- Every exit code is reachable and covered by a test.
